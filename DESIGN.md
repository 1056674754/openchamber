# OpenChamber UI Design Contract

This file records the design system already implemented by the fork. It is a
constraint for migration work, not a redesign brief.

## 1. Product Character

OpenChamber is a dense operational workspace. The interface prioritizes
scanning, repeated action, stable geometry, and long-running task context over
marketing composition. New upstream surfaces must look native to the existing
application and must not introduce a second visual language.

## 2. Color

- All UI colors come from semantic CSS variables generated by
  `packages/ui/src/lib/theme/` and exposed through
  `packages/ui/src/styles/design-system.css`.
- Components use semantic utilities such as `bg-background`, `bg-popover`,
  `bg-interactive-hover`, `text-foreground`, `text-muted-foreground`,
  `border-border`, `text-status-*`, and `text-syntax-*`.
- Raw palette classes and feature-local hex, RGB, or OKLCH values are not
  allowed. Theme presets own concrete color values.
- Selection, focus, status, and destructive states must remain distinguishable
  in every bundled light and dark theme.

## 3. Typography

- Semantic sizes are defined by `--text-markdown`, `--text-code`,
  `--text-ui-header`, `--text-ui-label`, `--text-meta`, and `--text-micro`.
- Components use the matching `typography-*` classes from
  `packages/ui/src/styles/typography.css`.
- The active theme supplies `--font-sans` and `--font-mono`.
- Letter spacing remains neutral unless an existing shared primitive defines
  it. Compact controls must not use display-scale text.

## 4. Spacing And Geometry

- The base spacing unit is 4px and the Tailwind spacing scale is multiplied by
  `--padding-scale`.
- App shells and panels use explicit `min-h-0` / `min-w-0` ownership so nested
  scroll containers do not resize their parents.
- Fixed controls keep stable dimensions. Cards and framed tools use the
  existing small-radius scale; page sections remain unframed.
- Chat content uses `chat-column`, `chat-input-column`, and
  `chat-message-column`; wide mode only changes their declared maximum width.

## 5. Shared Primitives

- Commands use `Button`; icon-only actions use the shared `Icon` component and
  an accessible label or tooltip.
- Menus, dialogs, selects, tooltips, scroll containers, overlays, inputs, and
  checkboxes come from `packages/ui/src/components/ui/`.
- Repeated tabs use the existing sortable/tab primitives. Panel content uses
  one owning scroll container rather than nested page cards.
- Composer syntax uses semantic token classes. The editor document remains a
  plain string; decoration must not change the submitted value.
- Sidebar and context-panel navigation preserve current project, server, and
  directory identity in both visual state and actions.

Required states for interactive primitives are default, hover, focus-visible,
active, disabled, selected, loading where asynchronous, and error where an
operation can fail.

## 6. Motion

- Motion communicates state or navigation only.
- Transitions are short and limited to opacity, transform, filter, color, or
  border changes. Layout properties are not animated.
- Respect reduced-motion preferences and avoid decorative looping animation.

## 7. Responsive Behavior

- Desktop, narrow desktop, tablet, mobile browser, Capacitor, and VS Code share
  business components but may use different shells.
- Mobile composer behavior must follow the visual viewport and safe-area
  variables without a second fullscreen editing model.
- The shared multi-instance `SessionSidebar` remains authoritative on mobile;
  upstream mobile-only sidebar replacements are not adopted.
- Context surfaces collapse or close intentionally on narrow viewports; they
  must never create horizontal page overflow.

## 8. Accessibility And Accepted Debt

- Native semantic controls, labels, keyboard navigation, visible focus for
  text-entry and menu surfaces, ARIA state, and sufficient theme contrast are
  required.
- IME composition must never trigger submit, history traversal, autocomplete
  acceptance, or destructive token edits.
- Accepted existing debt: global non-input focus styling is constrained by
  legacy CSS, and some large orchestrator components predate this contract.
  Migration work may decompose them incrementally but must not use that debt to
  remove behavior.
