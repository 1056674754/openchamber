1这个功能到底是什么

一句话:给某个会话挂一个"目标(objective)",然后由服务端循环驱动代理一轮一轮地干,直到独立的小模型审计认定目标完成。

关键认知:它不是 UI 插件,是一个跑在 Web 服务端的后台控制循环(packages/web/server/lib/session-goal/runtime.js,39KB)。循环通过 OpenCode 的 prompt_async 自动发送"继续"提示词,靠 SSE 事件感知会话空闲。即使关掉 UI 窗口,循环仍在服务端继续跑。

"Server-side control loop that keeps a session working toward a user-defined objective ... the loop lives in the web server and survives UI disconnects." — DOCUMENTATION.md

关键:审计员(小模型)是唯一的终止权威。代理自己没有任何渠道宣布自己的目标完成了——只有独立审计说 complete 才结算。所以"绿色 complete"是小模型的判断,不是代理的自证,这就是你说的"绿色又不一定真的完成"。

5控制语义 ★ 你遇到的两个问题

问题一:清除/暂停活动目标 → 杀掉正在跑的轮

这是故意的,不是 bug。sessionGoalActions.ts:

clearSessionGoal(sessionId, directory) {
  ...
  if (wasActive) {
    void abortCurrentOperation(sessionId);  // 杀当前轮
  }
}
setSessionGoalStatus(..., 'paused') {
  if (status === 'paused') {
    void abortCurrentOperation(sessionId);  // 杀当前轮
  }
}
"Pausing a goal from the UI also aborts the running turn (and vice versa — an abort pauses the goal), so 'stop' means stop on both axes." — DOCUMENTATION.md

你的直觉是对的: 清除"监工"≠ 停止工作。要停工作有专门的停止按钮。当前设计把两个语义绑死了。软清除方案:clearSessionGoal 里去掉 abortCurrentOperation,只移除 goal 元数据 + 删目标文件,服务端循环失去 active goal 自然停止续发(已有守卫:goal 改变时 drop continuation)。

问题二:完成后变绿"停住",没后续动作

  • complete 是终态之一,结算后循环不再续发(正确,不该继续跑)。
  • 但它不自动消失——goal 元数据保留在 session 上,目标条一直显示绿色。
  • 没有"标记完成 → 开新目标"的引导。用户只能:点开弹窗 → Clear → 重新 arm → 发新消息。三步。
  • 而且 complete 是小模型的判断,可能误判(代理其实没做完)。误判后既不自动续跑,也不提示用户复核,就静静停在那。

这确实是 UX 缺口。上游目前也没有针对它的改进(见成熟度分析)。

成熟度结论

仍在活跃开发,但核心已基本稳定、未冻结。

  • 主体于 2026-07-11/12 一次性 ship(当天 20+ 个 commit:循环、审计、暂停、文件目标、记账、移动端 UX…)。
  • clear/pause-abort 行为是 7/11 明确写死的设计(commit e7531675f "pausing a goal also aborts the agent's current turn"、c289c4d85 "removing an active goal aborts the running turn"、f939c1100 "pause goal on user abort instead of blocking it")。不是遗留 bug,是有意决策。
  • 7/27 之后的上游改动只有 3 个:147a6969b(7/28)、34bb3a6b2(7/30)、5c4bb5fab(7/31)——全是斜杠命令目标展开 / 控制面 / 创建管线的周边管线,没有动 clear/pause/complete 的 UX。
  • 没有上游改动涉及:清除/暂停不杀轮、完成后的后续动作、绿色完成态 UX。你关心的两点上游至今没碰。

结论: 做软清除改动不会和上游冲突(上游没在动这块);也不需要先 backport 那 3 个周边 commit(它们不影响 clear/pause 路径)。可以直接在我们当前合并点上改 sessionGoalActions.ts。
